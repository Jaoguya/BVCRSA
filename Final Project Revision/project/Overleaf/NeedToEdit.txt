B1. Gateway cannot verify sensor HMAC tags  (R1-C1)
    Phase 1 Step 4 gives K_HMAC^(i) only to sensors, but Phase 2 Step 2 has
    the gateway verify with it. The step cannot execute.
    FIX: provision the gateway with a master K_HMAC^mas and derive per-sensor
    keys via KDF. Patch Eq. gateway-keys, sensor-keys, credential-distribution,
    secret-state as follows:

      K_sel <-$ {0,1}^lambda,  K_HMAC^mas <-$ {0,1}^lambda,
      (pk_DO, sk_DO) <- DS.KeyGen(1^lambda)

      K_HMAC^(i) = KDF(K_HMAC^mas, ID_i || "hmac")

      Edge Gateway secret state: (K_sel, sk_DO, K_HMAC^mas)

    State explicitly: "The gateway derives K_HMAC^(i) for packet
    authentication but never obtains K_AES^(i), which is derived from the
    independent master key K_master retained by the TA. It can therefore
    verify sensor packets but cannot decrypt record contents."
    CONSEQUENCE: the gateway can then forge sensor packets. Theorem 1 must
    narrow its adversary class to exclude the gateway (hold against the
    cloud and external adversaries, not the gateway).

B2. ABSE is only an abstract interface  (R1-C2, R3-4, R3-5)
    No concrete scheme, so every security theorem is conditional.
    FIX -- describe an AND-gate policy scheme over a bilinear group
    (p, G1, GT, e, g), matching what abse_fast.py actually implements:

      Setup: alpha,beta <-$ Z_p; PP=(g, g^beta, e(g,g)^alpha), MSK=(alpha,beta)
      KeyGen(A subset U): r <-$ Z_p;
        SK_A = ( D = g^((alpha+r)/beta),
                 {D_a = g^r . H_g(a)^r_a,  D'_a = g^r_a}_{a in A} )
        (per-user r is what gives collusion resistance)
      Index/Token/Test: standard pairing-based keyword search, with epoch
        e_c and query id qid bound into the hash input so tokens are
        randomized and non-transferable across queries/epochs. Test
        evaluates a pairing equation that holds iff w=w' AND A |= P.
      Enc/Dec: same construction applied to a random G_T element, key
        derived via KDF.

    Security: DBDH in (G1, GT); keyword privacy against the cloud in the
    random-oracle model under DBDH; collusion resistance from independence
    of per-user r.

    Then state the implementation choice (also fixes A1):
      "The prototype instantiates the pairing group with BLS12-381 via
       py_arkworks_bls12381 (128-bit security), with a pure-Python BN128
       fallback through py_ecc. All reported measurements use the BLS12-381
       backend."
    Must be checked against abse_fast.py before submission.

B3. Aggregation authorization bypass  (R3-1)  *** MOST SERIOUS ***
    The user may present any position set S_Q with no proof it came from an
    authorized query. Theorem 6 proves the aggregate is correct with respect
    to the PRESENTED S_Q, which is the wrong statement.

    FIX -- new Phase 4 Step 4, inserted before aggregation:
      The cloud recomputes the conjunctive query bitmap from the matched
      node set U_Q it already holds from Step 1:
        B_Q^hat = AND_{j=1..d} OR_{u in U_Q ^ C_j} B_u~ XOR PRG(F(K_u,.), N_eq)
      and accepts the aggregation request only if
        S_Q subseteq Supp(B_Q^hat)  AND  |S_Q| <= N_eq
      aborting otherwise.

    KEY-AVAILABILITY PROBLEM: the cloud does not hold K_u (by design). Two
    resolutions:
      (a1) check on MASKED blocks only -- verifies each pos in S_Q falls in
           a block of a matched node, not that the bit is set. Weaker:
           catches cross-node theft, not within-node.
      (a2) user forwards recovered K_u for MATCHED nodes only, with the
           request -- full check, but reveals matched-node bitmap contents
           to the cloud (must be added to the leakage profile L_BVCRSA).
    RECOMMENDED: (a2) + B5 (TDA-side authorization check, folds together).
    The added leakage (matched-node bitmap contents) is no worse than what
    the cloud already learns (node identity, result cardinality, access
    pattern) -- state that in the threat model rather than hoping nobody
    notices.

    Add a new theorem (Aggregation Authorization): a user cannot obtain an
    aggregate over any position outside the bitmap generated by its own
    policy-authorized trapdoor, given the Step 4 check above.

    *** RELATED IMPLEMENTATION BUG, found 2026-08-16 ***
    user_client.py line 21 does  self.Ks = secrets["Ks"]  -- the code hands
    users the gateway selector key K_sel. The paper explicitly says
    "K_sel is never distributed to users". With K_sel a user can compute tags
    for ANY node, authorized or not. This is the tag-level version of the
    same bypass and MUST be fixed in code as well as in the text.

B4. Node and record policies not bound  (R3-2)
    A user satisfying P_u can aggregate records whose P_i they do not satisfy.
    FIX: containment invariant P_u => P_i, enforced at index construction.

B5. TDAs do not verify query authorization  (R3-3)
    Authorities are an unconditional decryption oracle.
    FIX: authorization attestation checked before partial release.
    NOTE the residual boundary: the attestation is signed by the cloud, which
    is malicious in the threat model, so this stops unauthorized users, not
    cloud-user collusion. State that limit explicitly.

B6. Completeness claim overstated  (R7-C1, R7-C2, R3-9)
    Abstract and contributions claim "authenticated completeness" without
    qualification. VQSA only proves the cloud returned what the GATEWAY
    committed.
    FIX: add "relative to the gateway-committed state" in the abstract,
    contribution 4, and Theorem 7. Then add this scope remark to the threat
    model, making the boundary unmissable:

      "Remark (Scope of Completeness). All completeness guarantees are
       stated relative to the state committed by the Edge Gateway. VQSA
       detects omission, modification, substitution, and replay by the
       cloud, but cannot detect fabricated canonical-node memberships or
       falsified bitmap contents produced by the gateway prior to
       anchoring. A gateway that commits an incorrect index is outside the
       threat model. Extending detection to gateway misbehaviour -- for
       example by requiring sensors to co-sign their canonical-node
       metadata so that fabricated memberships fail signature
       verification -- is left as future work."

    Worth including even as future work: it shows the limitation was
    understood rather than discovered by the reviewer.

B7. Theorem 2 needs a simulator argument  (R5-3, R3-6)
    FIX: real-or-simulated indistinguishability with explicit hybrids.
    Statement: there exists a PPT simulator S such that for every PPT
    adversary A and query sequence Q, the real and ideal (simulated-from-
    leakage) executions are indistinguishable up to negl(lambda), given
    ABSE token indistinguishability under DBDH and PRG security.

    Proof sketch: S is given only L_BVCRSA(Q) = (matched node sets, |S_Q|
    per query, dimension counts, access pattern, query pattern).
      H0: the real execution.
      H1: replace every token Tok_{j,i} with a uniformly random group
          element of the same form. H0 ~c H1 by ABSE token
          indistinguishability under DBDH (reduction uses (e_q, qid) as
          context binding so tokens for distinct queries are independently
          randomized).
      H2: replace every protected block B~_{u,b} for non-matched u with a
          uniformly random bitstring of the same length. H1 ~c H2 by PRG
          security, since K_u for non-matched nodes is never recovered by A.
      H2 is computable from L_BVCRSA(Q) alone -- set S := H2.

    Then add this remark conceding range-semantic leakage:
      "Theorem 2 guarantees only that nothing beyond L_BVCRSA is revealed;
       it does not claim the queried interval is hidden. Because canonical
       nodes correspond to fixed dyadic intervals, the matched set U_Q
       bounds [a_j,b_j] to within the granularity of one canonical node.
       Finer canonical partitions reduce this leakage at the cost of a
       larger cover size m_c and correspondingly larger trapdoors."
    The honest Theorem 2 is weaker than the current one -- weaker and
    provable beats stronger and hand-waved.

B8. Leakage understated  (R3-6, R3-7, R3-8)
    ADD two subsections to the leakage profile:

      "User-Side Leakage. An authorized user reconstructs the complete
       bitmap of every canonical node its attributes authorize, not merely
       the positions matching its query range. It therefore learns record
       membership for all positions of those nodes, which reveals
       approximate numerical values to within the granularity of one
       canonical interval, including for records outside its query result.
       This leakage is inherent to node-granular bitmap authorization;
       reducing it requires finer canonical partitioning, which increases
       the cover size m_c and hence trapdoor size and query cost.

       Gateway-Side Leakage. The Edge Gateway observes sensor identities,
       update times, searchable dimensions, canonical-node memberships, and
       bitmap positions in plaintext. Confidentiality of record contents
       and aggregate values is preserved -- the gateway holds neither
       K_AES^(i), the ABSE master secret, nor any threshold share -- but
       membership and metadata are not hidden from it."

    Also soften the query-privacy claim wherever it appears unqualified,
    per the Theorem 2 remark above (B7).

B9. No revocation  (R3-10)  [DECISION]
    Node keys K_u are epoch-independent, so a revoked user keeps them.
    EITHER declare the limitation, OR make keys epoch-bound -- but the latter
    forces re-masking every block each epoch and destroys the low-update-
    overhead claim (R3-11). Recommend declaring the limitation.

B10. No update/delete workflow  (R7-C3)
     ADD to Section III or the Discussion:

       "Record Invalidation. Although BVCRSA targets append-dominant
        workloads, expired or faulty readings must be invalidatable. To
        invalidate record i, the gateway (i) clears B_u[pos_i] <- 0 for
        every u in Path(u_{i,j}); (ii) increments nu_{u,b} for each
        affected block, forcing re-masking under a fresh PRG stream;
        (iii) marks the aggregation entry A_i as tombstoned so it is
        excluded from subsequent aggregation; and (iv) recomputes the
        affected sigma_{u,b}^bmp, Root_u^bmp, sigma_u^idx, and Root_{e_q}.
        Only blocks containing pos_i are re-masked; all others retain
        their existing version and commitment."

     Plus the remark that version binding does not achieve retroactive
     forgetting:
       "Version binding prevents an adversary from presenting a stale
        block as current, but a user that previously reconstructed
        B_{u,b} at version nu-1 retains that plaintext. Invalidation
        therefore prevents future disclosure and future aggregation, not
        retroactive forgetting by users already authorized at the time of
        ingestion."
