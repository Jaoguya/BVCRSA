B1. Gateway cannot verify sensor HMAC tags  (R1-C1)
    Phase 1 Step 4 gives K_HMAC^(i) only to sensors, but Phase 2 Step 2 has
    the gateway verify with it. The step cannot execute.
    FIX: provision the gateway with a master K_HMAC^mas and derive per-sensor
    keys. Full LaTeX in ImplementFIX/01 section F5.
    CONSEQUENCE: the gateway can then forge sensor packets. Theorem 1 must
    narrow its adversary class to exclude the gateway.

B2. ABSE is only an abstract interface  (R1-C2, R3-4, R3-5)
    No concrete scheme, so every security theorem is conditional.
    FIX: full instantiation written in ImplementFIX/01 section F4 -- Setup,
    KeyGen, Index/Token/Test, Enc/Dec, DBDH assumption, collusion argument.
    Must be checked against abse_fast.py before submission.

B3. Aggregation authorization bypass  (R3-1)  *** MOST SERIOUS ***
    The user may present any position set S_Q with no proof it came from an
    authorized query. Theorem 6 proves the aggregate is correct with respect
    to the PRESENTED S_Q, which is the wrong statement.
    FIX: new Phase 4 Step 4 (cloud recomputes B_Q and rejects S_Q not a
    subset), plus a new Theorem (Aggregation Authorization).
    LaTeX in ImplementFIX/01 F1 and 02.

    *** RELATED IMPLEMENTATION BUG, found 2026-08-16 ***
    user_client.py line 21 does  self.Ks = secrets["Ks"]  -- the code hands
    users the gateway selector key K_sel. The paper explicitly says
    "K_sel is never distributed to users". With K_sel a user can compute tags
    for ANY node, authorized or not. This is the tag-level version of the
    same bypass and MUST be fixed in code as well as in the text.

B4. Node and record policies not bound  (R3-2)
    A user satisfying P_u can aggregate records whose P_i they do not satisfy.
    FIX: containment invariant P_u => P_i, enforced at index construction.

B5. TDAs do not verify query authorization  (R3-3)
    Authorities are an unconditional decryption oracle.
    FIX: authorization attestation checked before partial release.
    NOTE the residual boundary: the attestation is signed by the cloud, which
    is malicious in the threat model, so this stops unauthorized users, not
    cloud-user collusion. State that limit explicitly.

B6. Completeness claim overstated  (R7-C1, R7-C2, R3-9)
    Abstract and contributions claim "authenticated completeness" without
    qualification. VQSA only proves the cloud returned what the GATEWAY
    committed.
    FIX: add "relative to the gateway-committed state" in the abstract,
    contribution 4, and Theorem 7. Add the scope remark from ImplementFIX/01 F6.

B7. Theorem 2 needs a simulator argument  (R5-3, R3-6)
    FIX: real-or-simulated indistinguishability with explicit hybrids, plus a
    remark conceding that U_Q reveals the queried range to canonical-node
    granularity. Full proof sketch in ImplementFIX/02.

B8. Leakage understated  (R3-6, R3-7, R3-8)
    ADD two subsections: user-side leakage (a user reconstructs the FULL
    bitmap of every authorized node, learning membership beyond its query)
    and gateway-side leakage. Text in ImplementFIX/03 F17.

B9. No revocation  (R3-10)  [DECISION]
    Node keys K_u are epoch-independent, so a revoked user keeps them.
    EITHER declare the limitation, OR make keys epoch-bound -- but the latter
    forces re-masking every block each epoch and destroys the low-update-
    overhead claim (R3-11). Recommend declaring the limitation.

B10. No update/delete workflow  (R7-C3)
     ADD the invalidation procedure from ImplementFIX/03 F18, including the
     remark that version binding does not achieve retroactive forgetting.

C2. [BLOCKING] Baseline comparison was plaintext-vs-plaintext
    Reviewer: R3-16, R5-2
--------------------------------------------------------------------------------

None of the four baselines performed cryptographic work in query():
  VC-KASE / Latt-IBEKS -- compared ct["value"] in plaintext
  Trinity              -- compared Hilbert integers
  ABSE-Range           -- counted every document whose search() did not raise

All four now perform their real per-document search operation, so the TIMING
is genuine. The MATCH DECISION for the baselines is taken from ground truth,
because these are reimplementations from published descriptions whose
synthetic parameters do not decrypt to a correct result set.

THIS MUST BE DISCLOSED. Add to Section V (full text in ImplementFIX/03 F11):

  "For reproducibility we note the following baseline implementation choices.
   Trinity is implemented as Trinity-I. VC-KASE is implemented with a
   prime-order group instantiated by modular exponentiation rather than a
   bilinear pairing; its verification cost is measured using real BLS12-381
   pairings. Latt-IBEKS follows Scheme-II for conjunctive queries with lattice
   dimension n=17 and modulus q=4093, which is smaller than a
   deployment-grade LWE parameterisation and therefore understates its cost.
   ABSE-Range performs attribute and keyword matching with real BLS12-381
   pairings but does not apply the numeric range predicate. For these three
   schemes the reported timings measure real cryptographic work while the
   returned result set is determined by ground truth; this is favourable to
   the baselines. BVCRSA derives its result set from real ABSE.Test tag
   agreement with no such assistance."

Omitting this makes the "comparable security settings" claim false.
